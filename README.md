# Competitive Programming Guide

This repository is a practical guide to classic algorithms and data structures. It is designed for people who want to learn how to recognize common problem patterns, understand the reasoning behind a solution, and practice implementing it in different programming languages.

The examples are organized as small, focused challenges inspired by competitive programming platforms such as LeetCode.

## Goals

- Learn the main algorithmic patterns.
- Practice translating an idea into code.
- Practice implementations in Python.
- Understand time and space complexity.
- Build a collection of reusable problem-solving techniques.

## Topics

The guide will grow to include topics such as:

- Arrays and strings
- Two pointers
- Sliding window
- Binary search
- Hash tables
- Stacks and queues
- Linked lists
- Trees and binary search trees
- Heaps and priority queues
- Graph traversal
- Backtracking
- Greedy algorithms
- Dynamic programming
- Sorting algorithms

## Repository structure

Each challenge can include:

```text
topic/
├── README.md              # Problem statement, examples, and explanation
└── solution.py            # Python implementation
```

The repository currently starts with this challenge:

- `two_sum_sorted.py` — Two Sum II challenge in Python

The current files contain the problem statement and a `TODO`; the solution is intentionally left for practice.

## How to practice

For each challenge:

1. Read the problem statement carefully.
2. Write down a few test cases, including edge cases.
3. Identify the relevant algorithmic pattern.
4. Implement the solution in one language.
5. Test the implementation manually and with automated tests when available.
6. Analyze the time and space complexity.
7. Compare the result with another language or approach.

## Solution format

Completed solutions should include:

- A short explanation of the approach.
- The main invariant or idea behind the algorithm.
- Time complexity.
- Space complexity.
- Clear, readable code.
- Tests for normal cases and edge cases.

## Learning principle

The goal is not only to memorize solutions. The important skill is learning how to identify a problem pattern and adapt a known technique to a new problem.
